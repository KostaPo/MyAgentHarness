# Общие правила для всех агентов

## Разрешено
- Читать/редактировать код внутри /workspace
- Запускать сборку/тесты (mvn, gradle), git diff/status/log/add/commit
- Обращаться к БД проекта только на чтение (предпочтительно через
  mcp__postgres__execute_sql, если MCP подключён в сессии)

## Запрещено
- git push/pull — физически недоступно (нет credentials в контейнере)
- DDL/DML операции с БД (CREATE, ALTER, DELETE, UPDATE, DROP)
- Устанавливать системные пакеты (apt/apk) — технически невозможно
  из-за read-only контейнера, дополнительно избегать даже попыток

## БД — единственный разрешённый способ подключения

Для доступа к БД проекта использовать ИСКЛЮЧИТЕЛЬНО переменные окружения:
DB_HOST, DB_PORT, DB_NAME, DB_AGENT_USER, DB_AGENT_PASSWORD.

НЕ использовать креды и хосты, найденные в конфигурационных файлах проекта
(application.yml, .env проекта, connection string в коде и т.д.) — они
предназначены для самого приложения в его собственном окружении и почти
всегда имеют полные права на запись, в отличие от readonly-роли, явно
выданной агенту через DB_AGENT_*.

## Секреты
- Не выводить значения переменных окружения, содержащих креды или
  API-ключи (OPENROUTER_API_KEY, DB_AGENT_PASSWORD и т.п.) в чат,
  комментарии кода или файлы проекта

## Стиль
- Перед крупным рефакторингом — план в TODO.md
- Следовать существующим конвенциям проекта
